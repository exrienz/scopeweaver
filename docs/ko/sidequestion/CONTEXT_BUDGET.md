# 긴 곁가지 대화와 맥락 예산

[English](../../../sidequestion/CONTEXT_BUDGET.md) · 한국어 · [简体中文](../../zh-Hans/sidequestion/CONTEXT_BUDGET.md) · [繁體中文](../../zh-Hant/sidequestion/CONTEXT_BUDGET.md) · [日本語](../../ja/sidequestion/CONTEXT_BUDGET.md) · [Español](../../es/sidequestion/CONTEXT_BUDGET.md)

2026-09-11 원본 수정 기록입니다. 이전 구현은 요청 JSON 글자 수를 토큰 수로 간주하고 주 작업의 32K 출력 예약을 이어받았습니다. HTML, JavaScript와 도구 결과가 많으면 정상 곁가지 질문도 너무 일찍 거부했습니다.

## 검토한 오픈 소스 구현

- [Grok CLI 곁가지 맥락](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/agent.ts#L739): 최근 사용자/어시스턴트 텍스트에서 약 2000자 예산, 메시지당 최대 400자를 추출합니다. 해당 경로에는 연속 곁가지 문답 기록이 없습니다.
- [Grok CLI 독립 요청](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/utils/side-question.ts): 독립 취소 신호, 지원 모델의 출력 상한 2048토큰, 도구 없음.
- [Grok CLI 주 세션 압축](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/compaction.ts): 토큰 추정, 최근 내용 보존, 기존 요약에 새 내용 반영, 턴 간 잘림 처리.
- [OpenCode 세션 압축](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/compaction.ts): 전체 요청 추정, 출력/버퍼 예약, 최근 내용과 누적 요약, 도구 없는 요약 요청. 해당 구현의 기본 최근 예산은 8000, 요약 출력 상한은 4096토큰입니다.
- [OpenCode 초과 복구](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/runner/llm.ts): 어시스턴트 출력 전만 복구하고 복구된 호출은 같은 복구 경로에 다시 들어가지 않습니다.

ARTEX는 독립 출력 예산, 최근 내용과 누적 요약, 제한된 복구 방식을 참고했습니다. Grok의 텍스트 발췌 대신 norma v0.3.6의 구조화 메시지와 도구 짝을 유지했습니다. OpenCode식 주 세션 압축 이벤트를 ARTEX 주 transcript에 기록하지 않았습니다. ScopeWeaver도 이 설계를 유지하며 버전 표기는 당시 구현을 가리킵니다.

## 요청 예산과 실행

- norma의 내용 블록 UTF-8 바이트 추정과 4/3 여유분을 사용하고 시스템 지침, 도구 스키마, 메시지 포장 비용을 더합니다. 모델의 정확한 토큰 수는 아닙니다.
- 곁가지 출력은 기본 최대 8192토큰이며 주 설정의 출력 상한도 넘지 않습니다. 서버 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS`로 256~32768 상한을 지정할 수 있습니다. 제품 기본 모델이나 주 작업 매개변수는 바꾸지 않습니다.
- 입력 예산은 맥락 창에서 출력 상한과 안전 여유를 뺀 값입니다. 창을 모르면 플랫폼 기본 200K를 씁니다. 안전 여유는 창의 5%이며 최소 128, 최대 8192토큰입니다.
- 성공 문답은 순번 오름차순으로 최대 20쌍씩 읽습니다. 원문 최대 20쌍을 유지하며 입력 예산의 1/4, 최대 16K토큰을 사용합니다.
- 초과 문답은 출처와 맥락 시각을 포함한 누적 요약으로 반영합니다. 과거 어시스턴트 답변은 새 도구 증거가 아니며 충돌 시 최신 주 스냅샷을 우선합니다.
- 주 맥락이 여전히 길면 복사본의 오래된 메시지만 요약합니다. 최근 내용은 최대 8K토큰을 유지하며 도구 호출과 결과를 나누지 않습니다. 한 묶음이 너무 크면 전체를 요약합니다.
- 요약 입력은 남은 창에 맞춰 UTF-8 경계를 지켜 나누며 출력 상한은 2048토큰입니다. 빈 요약, 잘린 요약, 도구 호출, 예산 초과 요약은 캐시하지 않습니다. 곁가지 요청당 요약 호출은 최대 12회이고 같은 120초 제한에 포함됩니다. 상한 도달 시 명시적으로 실패합니다.
- 첫 모델 맥락 초과 오류가 텍스트/도구 호출 출력 전에 발생하면 더 줄여 한 번 재시도합니다. 추정 크기가 줄지 않으면 즉시 복구를 중단합니다. 다른 모델 오류나 일부 스트리밍 후에는 이 복구를 하지 않습니다.
- 요약, 실패 시도, 취소를 포함해 받은 사용량을 같은 곁가지 요청에 합산합니다. Provider가 사용량을 반환하지 않으면 0만 기록하며 추정치를 실측처럼 기록하지 않습니다.

## 저장과 화면

`side_question_sessions.memory`는 오래된 문답 요약, 포함한 ordinal, 스냅샷 식별자별 주 맥락 요약 캐시를 저장합니다. `side_question_requests.context_info`는 준비 단계, 실제 재생 문답 수, 요약 사용 여부, 예산 추정을 저장합니다.

요약은 원 요청이 실행 중이고 비우기 버전이 맞을 때만 저장합니다. 비우기는 캐시도 지워 늦은 쓰기가 삭제 데이터를 되살리지 못합니다. 새 스냅샷은 이전 요약을 재사용하지 않습니다. v3 보관에 요약 필드가 포함되며 해당 필드 없는 이전 v3은 빈 객체로 복원합니다. v1/v2도 호환됩니다.

POST는 요청을 받아 반환한 뒤 백그라운드에서 준비/압축하며 이 과정에 진입 잠금이나 DB 트랜잭션을 유지하지 않습니다. SSE/기록에는 준비, 문답 정리, 복사본 압축, 답변 단계를 표시합니다. 압축 실패는 요청의 실패 종료 상태로 저장합니다. 프런트엔드는 오류를 남기고 실패 질문 초안을 복구하며 입력창을 덮는 토스트는 띄우지 않습니다. 기록 폴링도 제출 오류를 지우지 않습니다.
