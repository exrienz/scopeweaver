# 介面本地化

各語言版本請見本頁上方導覽。

預設英文；已提供英文、韓文、簡體中文（`zh-Hans`）、繁體中文（`zh-Hant`）、日文（`ja`）與西班牙文（`es`）。React provider 在 hydration 後還原明確偏好，保持靜態英文匯出與首次用戶端轉譯一致。選擇儲存在 localStorage 的 `scopeweaver.locale` 與 `scopeweaver_locale` cookie。即使 hydration 尚未完成，API 傳輸也會讀取已儲存偏好；無法使用 localStorage 時改讀 cookie。不會自動採用作業系統／瀏覽器語言。

<a id="adding-a-language"></a>

## 新增語言

1. 在前端匯入、Go 內嵌的共用宣告 `locale/definitions.json` 新增經審查的標準 ID、原生名稱、Intl 語系與別名。在 `locale/matching-vectors.json` 新增接受及拒絕範例。依需要擴充前端 `Locale` 型別與後端語言常數；完整性檢查必須與宣告一致。勿修改既有 EN／KO 別名。
2. 為六個命名空間撰寫每個目前英文鍵的譯文。英文定義 `MessageKey` 型別與含義。在 `catalog.ts` 註冊新的具型別命名空間表格；不得發布英文複本或靠執行時備援隱藏缺漏。`messages/zh-hans.ts` 示範依每個英文命名空間檢查的獨立資源。插值欄位名稱與成對 rich tag（包括重複標籤）必須相容。技術識別碼、程式碼與通訊協定字串維持原樣。
3. 在 `calendar.ts` 加入 date-fns 物件。原生選擇器標籤與 Intl 格式來自共用宣告；`Calendar` 與範圍標籤使用集中式 date-fns 對應。呼叫端提供的行事曆語系或格式器仍優先。
4. 提供後端依語言索引的目錄及全部外部正式註冊。`locale.Register(key, en, ko)` 保持相容，其他語言使用 `locale.RegisterAll(map[string]map[locale.Lang]string{key: {locale.En: en, locale.Ko: ko, locale.ZhHans: zh}})`。請檢查原始註冊，勿以 `Lookup` 判斷；後者會對未知或不完整註冊保留英文／鍵備援。此執行時相容性備援**不符合**發行完整度要求。
5. 新增聚焦的正規化、完整性、狀態與瀏覽器情境。執行前端測試、型別檢查、靜態匯出、後端目錄／註冊測試，以及 [CONTRIBUTING.md](../../CONTRIBUTING.zh-Hant.md) 的必要儲存庫檢查。記錄翻譯審查疑慮與處理結果。未驗證時不得將獨立審查描述為母語者核准。六種語言皆維護對應使用者／貢獻者指南，包括英文／韓文功能文件。
6. 同步獨立配接器標準 ID 清單（`adapters/agent/src/client.js` 的 `SUPPORTED_LANGUAGES`）與根目錄 shell／批次訊息輔助。封裝配接器自帶清單，不得在執行時依賴儲存庫根目錄 JSON。執行 `node e2e/script-locales.mjs` 檢查配接器與語系登錄表的一致性、別名、shell 訊息、插值與可拋棄指令碼流程；其中 Windows 檢查僅檢視批次結構。原生 Windows 啟動器對等須在 Windows 執行 `node e2e/windows-launcher.mjs` 或由 Windows CI 驗證。

比對不區分大小寫，並接受以底線分隔的地區格式。`zh`、`zh-CN`、`zh-SG` 明確對應 `zh-Hans`；`zh-Hans` 加地區亦可比對。明確文字系統優先於地區，因此 `zh-Hans-TW` 為簡體中文。繁體輸入（`zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO`，含 `zh-Hant-CN`）解析為 `zh-Hant`，絕不選簡體中文。日文與西班牙文地區標籤分別對應 `ja`、`es`；不支援的語言改試下一偏好或預設值。明確指定互相衝突的中文字體系統仍不受支援。

<a id="runtime-boundaries"></a>

## 執行時邊界

元件使用 `useI18n().t`，非 React 輔助函式使用 `translate`。已發布目錄包含每個鍵；未知前端鍵顯示鍵本身。使用者值透過插值參數傳入。絕不翻譯使用者輸入、持久報告、原始證據、識別碼、API 欄位名稱、憑證或通訊協定值。既有中文 mention 傳輸標籤及歷史剖析別名維持後端相容，顯示標籤另行本地化。

`interface` 命名空間包含已遷移的介面與自撰示範訊息，使用穩定 ID；`english` 涵蓋既有英文標籤。新功能應在適當命名空間使用具描述性的鍵。靜態設定物件透過 getter 提供本地化標籤。使用者訂閱語系；memoized 衍生標籤須將語系納入相依項目。切換語言不會重新掛載應用程式或清空草稿。

`localizedFetch` 加入語系標頭與查詢參數，同時保留呼叫端明確覆寫及驗證。SSE URL 使用 `sseUrl`，自動加入語系查詢參數。日期與數字使用 `getIntlLocale` 或 `fmt`。

`prepareDemoFixture` 僅套用於自撰初始測試資料。編輯會以一般可寫值取代 accessor；`cloneDemoFixture` 保留此區別。自訂值即使恰好等於譯文，也保持不變。

<a id="verification"></a>

## 驗證

在 `web` 執行 `npm test`、`npx tsc --noEmit` 與 `npm run build:static`。測試涵蓋所有已發布目錄、缺漏／空值／預留位置／rich tag 反例、共用語系向量、持久化／hydration、API／SSE 傳輸、可編輯測試資料、舊版 mention、Intl／date-fns 格式與呼叫端覆寫。AST 漢字檢查僅豁免六個中文資源物件中的直接字串值；該檔中的程式碼、一般介面來源與來源／設定註解仍受檢查。新增資源需同樣狹窄且經審查的允許範圍，絕不豁免整個目錄。EN／KO 目錄保留未翻譯漢字檢查。繁體中文與日文資源亦僅允許直接字串值；西班牙文不豁免。

必要 `e2e` 基本測試使用同一簽出版本的內嵌執行檔與全新可拋棄資料庫，保留 EN／KO 檢查，並檢查六種語言的設定／登入／任務／設定／對話草稿、偏好還原、首次 API 傳輸、SSE 重連／篩選保留與實際數字格式。既有儀表板 token 迴歸仍包含在 `npm run smoke`。範圍選擇器目前沒有已掛載的正式呼叫端，因此 date-fns／範圍及明確行事曆覆寫行為由聚焦純函式測試驗證；未掛載並操作真實呼叫端時，不得宣稱有瀏覽器行事曆證據。
