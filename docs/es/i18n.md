# Localización de interfaz

[English](../../web/src/i18n/README.md) · [한국어](../ko/i18n.md) · [简体中文](../zh-Hans/i18n.md) · [繁體中文](../zh-Hant/i18n.md) · [日本語](../ja/i18n.md) · Español

El inglés es predeterminado. Se incluyen inglés, coreano, chino simplificado (`zh-Hans`), tradicional (`zh-Hant`), japonés (`ja`) y español (`es`). El proveedor React restaura preferencias explícitas tras hidratar, manteniendo exportación inglesa y primer render coherentes. La selección persiste en localStorage `scopeweaver.locale` y cookie `scopeweaver_locale`. La API lee la preferencia incluso antes de hidratar; si localStorage falla, usa cookie. No se elige automáticamente idioma de sistema/navegador.

## Añadir un idioma

1. Añade ID canónico revisado, nombre nativo, idioma Intl y alias a `locale/definitions.json`, declaración importada por frontend e integrada por Go. Añade casos aceptados/rechazados a `locale/matching-vectors.json`. Amplía tipo `Locale` y constantes backend si hace falta; sus comprobaciones deben concordar. No cambies alias históricos EN/KO.
2. Escribe cada clave inglesa actual en los seis espacios. El inglés define tipo `MessageKey` y significado. Registra tablas tipadas nuevas en `catalog.ts`; nunca publiques copias inglesas ni uses alternativas dinámicas para ocultar traducciones ausentes. `messages/zh-hans.ts` muestra un recurso separado comprobado contra cada espacio inglés. Conserva nombres de interpolación y etiquetas emparejadas, incluidas repeticiones. Identificadores, código y protocolos no cambian.
3. Añade objeto date-fns a `calendar.ts`. Etiquetas nativas e Intl vienen de la declaración; `Calendar` y rangos usan el mapa central. Un idioma o formateador de calendario explícito sigue prevaleciendo.
4. Proporciona catálogos backend por idioma y cada registro externo de producción. `locale.Register(key, en, ko)` sigue compatible, pero los adicionales usan `locale.RegisterAll(map[string]map[locale.Lang]string{key: {locale.En: en, locale.Ko: ko, locale.ZhHans: zh}})`. Comprueba registros originales, no `Lookup`, que mantiene alternativa inglesa/de clave para registros desconocidos/incompletos del llamante. Esa compatibilidad **no** satisface integridad de publicación.
5. Añade escenarios de normalización, integridad, estado y navegador. Ejecuta pruebas frontend, tipos, exportación, catálogo/registros backend y controles de [CONTRIBUTING.md](../../CONTRIBUTING.es.md). Documenta dudas y resolución de traducciones. No describas revisión independiente como aprobación nativa sin verificar. Mantén guías correspondientes en seis idiomas, incluidas funciones en inglés/coreano.
6. Mantén sincronizados la lista de ID canónicos del adaptador independiente (`SUPPORTED_LANGUAGES` en `adapters/agent/src/client.js`) y los auxiliares de mensajes shell/batch de la raíz. Los adaptadores empaquetados incluyen su propia lista y no deben depender durante la ejecución del JSON de la raíz del repositorio. Ejecuta `node e2e/script-locales.mjs` para comprobar paridad del adaptador/registro, alias, mensajes shell, interpolación y flujos de scripts desechables; sus comprobaciones de Windows solo inspeccionan la estructura batch. La paridad nativa del iniciador de Windows requiere `node e2e/windows-launcher.mjs` en Windows o el trabajo CI de Windows.

La coincidencia ignora mayúsculas y acepta guiones bajos regionales. `zh`, `zh-CN` y `zh-SG` van a `zh-Hans`; `zh-Hans` con región también. La escritura explícita prevalece: `zh-Hans-TW` es simplificado. Entradas tradicionales (`zh-Hant`, `zh-TW`, `zh-HK`, `zh-MO`, incluido `zh-Hant-CN`) van a `zh-Hant`, nunca simplificado. Etiquetas regionales japonesas/españolas van a `ja`/`es`; idiomas no compatibles pasan a la siguiente preferencia o valor predeterminado. Escrituras chinas explícitas contradictorias siguen no admitidas.

## Límites durante la ejecución

Usa `useI18n().t` en componentes y `translate` fuera de React. Los catálogos incluyen todas las claves; las desconocidas se muestran a sí mismas. Pasa valores de usuario como interpolación. Nunca traduzcas texto introducido, informes persistentes, pruebas originales, identificadores, nombres API, credenciales ni valores de protocolo. Las etiquetas chinas de menciones y alias históricos siguen compatibles con backend; las visibles se localizan aparte.

`interface` contiene interfaz migrada y demostración redactada con ID estables. `english` cubre etiquetas inglesas previas. Funciones nuevas usan claves descriptivas apropiadas. Objetos estáticos exponen etiquetas localizadas por getters. Los consumidores se suscriben al idioma; las etiquetas derivadas memorizadas lo incluyen como dependencia. Cambiar no remonta la aplicación ni borra borradores.

`localizedFetch` añade cabeceras y parámetros manteniendo anulaciones explícitas y autenticación. SSE usa `sseUrl`, que añade idioma en consulta. Usa `getIntlLocale` o `fmt` para fechas/números.

`prepareDemoFixture` solo se ejecuta en datos iniciales redactados. Editar sustituye el accesor por un valor normal escribible; `cloneDemoFixture` conserva la diferencia. Los valores personalizados no cambian aunque coincidan con una traducción.

## Verificación

Ejecuta `npm test` desde `web`, `npx tsc --noEmit` y `npm run build:static`. Cubren catálogos, negativos de claves vacías/ausentes/marcadores/etiquetas, vectores, persistencia/hidratación, API/SSE, datos editables, menciones antiguas, formatos Intl/date-fns y anulaciones. El control AST de Han solo exime cadenas directas de los seis objetos de recursos chinos; código del archivo, UI normal y comentarios siguen protegidos. Un recurso nuevo necesita excepción igualmente limitada y revisada, nunca por directorio. EN/KO conservan controles de Han sin traducir. Tradicional y japonés tienen la misma excepción directa limitada; español ninguna.

La prueba básica obligatoria `e2e` usa binario integrado de la misma copia y BD nueva desechable. Conserva EN/KO y comprueba seis idiomas para borradores de configuración/acceso/tarea/ajustes/chat, restauración, primera API, SSE/filtros y números. La regresión de tokens del panel sigue en `npm run smoke`. El selector de rango no tiene consumidor montado de producción; date-fns/rangos y anulaciones explícitas tienen pruebas puras. No informes prueba de calendario en navegador sin montar y ejercitar un consumidor real.
