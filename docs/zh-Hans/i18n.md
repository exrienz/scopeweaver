# 界面本地化

各语言版本请见本页上方导览。

默认英文；已提供英文、韩文、简体中文（`zh-Hans`）、繁体中文（`zh-Hant`）、日文（`ja`）与西班牙文（`es`）。React provider 在 hydration 后恢复明确偏好，保持静态英文导出与首次客户端渲染一致。选择保存在 localStorage 的 `scopeweaver.locale` 与 `scopeweaver_locale` cookie。即使 hydration 尚未完成，API 传输也会读取已保存偏好；无法使用 localStorage 时改读 cookie。不会自动采用操作系统／浏览器语言。

<a id="adding-a-language"></a>

## 新增语言

1. 在前端导入、Go 内嵌的共用声明 `locale/definitions.json` 新增经审查的标准 ID、原生名称、Intl 语言区域与别名。在 `locale/matching-vectors.json` 新增接受及拒绝示例。依需要扩展前端 `Locale` 类型与后端语言常量；完整性检查必须与声明一致。勿修改既有 EN／KO 别名。
2. 为六个命名空间撰写每个目前英文键的译文。英文定义 `MessageKey` 类型与含义。在 `catalog.ts` 注册新的具类型命名空间表格；不得发布英文复本或靠运行时回退隐藏缺漏。`messages/zh-hans.ts` 示范依每个英文命名空间检查的独立资源。插值字段名称与成对 rich tag（包括重复标签）必须兼容。技术识别码、代码与协议字串维持原样。
3. 在 `calendar.ts` 加入 date-fns 对象。原生选择器标签与 Intl 格式来自共用声明；`Calendar` 与范围标签使用集中式 date-fns 对应。呼叫端提供的行事历语言区域或格式器仍优先。
4. 提供后端依语言索引的目录及全部外部正式注册。`locale.Register(key, en, ko)` 保持兼容，其他语言使用 `locale.RegisterAll(map[string]map[locale.Lang]string{key: {locale.En: en, locale.Ko: ko, locale.ZhHans: zh}})`。请检查原始注册，勿以 `Lookup` 判断；后者会对未知或不完整注册保留英文／键回退。此运行时兼容性回退**不符合**发行完整度要求。
5. 新增聚焦的正规化、完整性、状态与浏览器情境。运行前端测试、类型检查、静态导出、后端目录／注册测试，以及 [CONTRIBUTING.md](../../CONTRIBUTING.zh-Hans.md) 的必要仓库检查。记录翻译审查疑虑与处理结果。未验证时不得将独立审查描述为母语者审批。六种语言皆维护对应用户／贡献者指南，包括英文／韩文功能文件。
6. 同步独立适配器标准 ID 清单（`adapters/agent/src/client.js` 的 `SUPPORTED_LANGUAGES`）与根目录 shell／批次消息辅助。封装适配器自带清单，不得在运行时依赖仓库根目录 JSON。运行 `node e2e/script-locales.mjs` 检查适配器与语言区域注册表的一致性、别名、shell 消息、插值与可抛弃脚本流程；其中 Windows 检查仅检视批次结构。原生 Windows 启动器对等须在 Windows 运行 `node e2e/windows-launcher.mjs` 或由 Windows CI 验证。

比对不区分大小写，并接受以底线分隔的地区格式。`zh`、`zh-CN`、`zh-SG` 明确对应 `zh-Hans`；`zh-Hans` 加地区亦可比对。明确文字系统优先于地区，因此 `zh-Hans-TW` 为简体中文。繁体输入（`zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO`，含 `zh-Hant-CN`）解析为 `zh-Hant`，绝不选简体中文。日文与西班牙文地区标签分别对应 `ja`、`es`；不支持的语言改试下一偏好或默认值。明确指定互相冲突的中文字体系统仍不受支持。

<a id="runtime-boundaries"></a>

## 运行时边界

元件使用 `useI18n().t`，非 React 辅助函数使用 `translate`。已发布目录包含每个键；未知前端键显示键本身。用户值通过插值参数传入。绝不翻译用户输入、持久报告、原始证据、识别码、API 字段名称、凭证或协议值。既有中文 mention 传输标签及历史剖析别名维持后端兼容，显示标签另行本地化。

`interface` 命名空间包含已迁移的界面与自撰示范消息，使用稳定 ID；`english` 涵盖既有英文标签。新功能应在适当命名空间使用具描述性的键。静态配置对象通过 getter 提供本地化标签。用户订阅语言区域；memoized 衍生标签须将语言区域纳入依赖项目。切换语言不会重新挂载应用程序或清空草稿。

`localizedFetch` 加入语言区域头部与查询参数，同时保留呼叫端明确覆写及验证。SSE URL 使用 `sseUrl`，自动加入语言区域查询参数。日期与数字使用 `getIntlLocale` 或 `fmt`。

`prepareDemoFixture` 仅应用于自撰初始测试数据。编辑会以一般可写值取代 accessor；`cloneDemoFixture` 保留此区别。自定义值即使恰好等于译文，也保持不变。

<a id="verification"></a>

## 验证

在 `web` 运行 `npm test`、`npx tsc --noEmit` 与 `npm run build:static`。测试涵盖所有已发布目录、缺漏／空值／占位符／rich tag 反例、共用语言区域向量、持久化／hydration、API／SSE 传输、可编辑测试数据、旧版 mention、Intl／date-fns 格式与呼叫端覆写。AST 汉字检查仅豁免六个中文资源对象中的直接字串值；该档中的代码、一般界面来源与来源／配置注解仍受检查。新增资源需同样狭窄且经审查的允许范围，绝不豁免整个目录。EN／KO 目录保留未翻译汉字检查。繁体中文与日文资源亦仅允许直接字串值；西班牙文不豁免。

必要 `e2e` 基本测试使用同一签出版本的内嵌可执行文件与全新可抛弃数据库，保留 EN／KO 检查，并检查六种语言的配置／登录／任务／配置／对话草稿、偏好恢复、首次 API 传输、SSE 重连／筛选保留与实际数字格式。既有仪表板 token 回归仍包含在 `npm run smoke`。范围选择器目前没有已挂载的正式呼叫端，因此 date-fns／范围及明确行事历覆写行为由聚焦纯函数测试验证；未挂载并操作真实呼叫端时，不得宣称有浏览器行事历证据。
