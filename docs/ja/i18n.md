# 画面のローカライズ



既定の言語は英語です。英語、韓国語、簡体字中国語（`zh-Hans`）、繁体字中国語（`zh-Hant`）、日本語（`ja`）、スペイン語（`es`）を提供します。React のプロバイダーはハイドレーション後に明示的な言語設定を復元し、静的な英語のエクスポートと最初のクライアント描画を一致させます。選択は localStorage の `scopeweaver.locale` と Cookie の `scopeweaver_locale` に保存します。API 通信はハイドレーション完了前でも保存済みの設定を読み、localStorage が利用できなければ Cookie に戻ります。OS・ブラウザーの言語は自動選択しません。

<a id="adding-a-language"></a>
## 言語の追加

1. フロントエンドがインポートし Go が埋め込む共有宣言 `locale/definitions.json` に、レビュー済みの正規 ID、言語の自称、Intl ロケール、別名を追加します。`locale/matching-vectors.json` に受理・拒否の例を追加してください。必要に応じてフロントエンドの `Locale` 型とバックエンドの言語定数を拡張し、完全性の検査を宣言と一致させます。過去の EN/KO の別名は変更しないでください。
2. 6 つの名前空間すべてで、現在の英語の全キーを翻訳します。英語が `MessageKey` の型と意味を定義します。新しい型付きの名前空間テーブルを `catalog.ts` に登録し、英語のコピーを出荷したり、実行時のフォールバックで翻訳不足を隠したりしないでください。`messages/zh-hans.ts` は、各英語の名前空間と照合する独立したリソースの例です。補間のフィールド名と、繰り返しを含む対のリッチテキストタグの互換性を保ってください。技術的識別子、コード、プロトコルの文字列は変更しません。
3. date-fns のオブジェクトを `calendar.ts` に追加します。言語選択の自称ラベルと Intl の形式は共有宣言から取得し、`Calendar` と範囲ラベルは集約した date-fns の対応を使います。呼び出し元が渡すカレンダーのロケール・フォーマッターは引き続き優先します。
4. バックエンドの言語別カタログと、外部の本番登録をすべて用意します。`locale.Register(key, en, ko)` は互換性を保ちますが、追加言語では `locale.RegisterAll(map[string]map[locale.Lang]string{key: {locale.En: en, locale.Ko: ko, locale.ZhHans: zh}})` を使います。`Lookup` は不明・不完全な呼び出し元登録に英語・キーへのフォールバックを残すため、生の登録を検査してください。この実行時の互換性フォールバックは、出荷時の完全性を**満たしません**。
5. 正規化、整合性、状態、ブラウザーの対象を絞ったシナリオを追加します。フロントエンドのテスト、型検査、静的エクスポート、バックエンドのカタログ・登録テストと、[CONTRIBUTING.md](../../CONTRIBUTING.ja.md) の必須検査を実行してください。翻訳レビューの懸念と解決を記録し、独立したレビューを、確認なしに母語話者の承認と表現してはいけません。英語・韓国語の機能ドキュメントも含め、6 言語の利用者・貢献者向けガイドを対応させて保守してください。
6. 単独で配布するアダプターの正規 ID 一覧（`adapters/agent/src/client.js` の `SUPPORTED_LANGUAGES`）と、ルートのシェル・バッチ用メッセージヘルパーも同期します。配布パッケージのアダプターは独自の一覧を持ち、実行時にリポジトリルートの JSON に依存してはいけません。`node e2e/script-locales.mjs` でアダプターと共有宣言の対応、別名、シェルの文言、変数の埋め込み、使い捨てのスクリプト実行を確認します。このテストの Windows 検査はバッチの構造確認に限ります。Windows ランチャーの実動作を揃えるには、Windows 上の `node e2e/windows-launcher.mjs` または Windows CI ジョブが必要です。

照合は大文字・小文字を区別せず、アンダースコア付きの地域形式も受け付けます。`zh` 単独、`zh-CN`、`zh-SG` は明示的に `zh-Hans` へ対応し、`zh-Hans` に地域を付けた形式も一致します。明示した文字体系が地域より優先するため、`zh-Hans-TW` は簡体字中国語です。繁体字の入力（`zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant-CN` を含む）は `zh-Hant` に解決し、簡体字には決して解決しません。日本語とスペイン語の地域タグは `ja` と `es` に解決し、未対応の言語は次の設定または既定値に進みます。明示的な中国語の文字体系が競合する入力は、引き続き未対応です。

<a id="runtime-boundaries"></a>
## 実行時の境界

コンポーネントでは `useI18n().t`、React 外のヘルパーでは `translate` を使用します。出荷カタログは全キーを持ち、不明なフロントエンドのキーはそのまま表示します。ユーザーの値は補間パラメーターとして渡してください。ユーザー入力、保存済みのレポート、生の証拠、識別子、API フィールド名、認証情報、プロトコルの値は決して翻訳しないでください。既存の中国語のメンションの通信ラベルと過去のパーサーの別名は、バックエンドとの互換性を保ち、表示ラベルは独立してローカライズします。

`interface` 名前空間には、移行した画面と作成済みデモのメッセージを安定した ID で格納します。`english` 名前空間は既存の英語ラベルを対象にします。新機能は適切な名前空間に説明的なキーを追加します。静的な設定オブジェクトは getter でローカライズしたラベルを公開します。利用側はロケールを購読し、メモ化した派生ラベルの依存関係にも含めます。言語の切り替えでアプリケーションを再マウントしたり、下書きを消したりしません。

`localizedFetch` は、呼び出し元の明示的な上書きと認証を保持しながら、言語のヘッダーとクエリパラメーターを追加します。SSE の URL には、言語のクエリパラメーターを加える `sseUrl` を使います。日付・数値には `getIntlLocale` または `fmt` を使ってください。

`prepareDemoFixture` は作成済みの初期テストデータにのみ適用します。編集するとアクセサーを通常の書き込み可能な値に置き換え、`cloneDemoFixture` はこの違いを保持します。カスタム値は、翻訳文と同じ値でも変更しません。

<a id="verification"></a>
## 検証

`web` から `npm test`、`npx tsc --noEmit`、`npm run build:static` を実行してください。テストは全出荷カタログ、欠落・空・プレースホルダー・リッチタグの異常系、共有ロケールベクトル、保存とハイドレーション、API/SSE 通信、編集可能なデモデータ、過去のメンション、Intl/date-fns の形式、呼び出し元の上書きを対象にします。AST の漢字ガードの例外は、中国語リソースの 6 つのオブジェクト内の直接の文字列値だけで、そのファイル内のコード、通常の UI ソース、ソース・設定のコメントは引き続き検査します。新リソースにも同じ程度に限定したレビュー済みの例外が必要で、ディレクトリ全体を除外してはいけません。EN/KO カタログでは未翻訳の漢字の検査を保持します。繁体字中国語と日本語も同様に直接値だけを狭く許可し、スペイン語には例外を設けません。

必須の `e2e` スモークテストは、同じチェックアウトの UI 埋め込みバイナリと新しい使い捨て DB を使います。EN/KO の確認を保持し、6 言語で初期設定・ログイン・タスク・設定・チャットの下書き、設定の復元、最初の API 通信、SSE 再接続と絞り込みの保持、数値の表示形式を確認します。既存のダッシュボードのトークン回帰テストも `npm run smoke` に含めます。範囲ピッカーは現在、本番の呼び出し元にマウントされていないため、date-fns・範囲と明示的なカレンダー上書きの動作は、対象を絞った純粋関数のテストで確認します。実際の呼び出し元にマウントして操作しない限り、ブラウザーでカレンダーを実証したとは報告しないでください。
