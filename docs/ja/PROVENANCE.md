# ScopeWeaver の出典と変更内容



ScopeWeaver は [Autumn-27/ARTEX](https://github.com/Autumn-27/ARTEX) のコミット `160fe13` を基にした独立した派生物です。[cskwork/scopeweaver](https://github.com/cskwork/scopeweaver) で個別に保守され、GitHub のフォークネットワーク上の関係はありません。

**2026-10-02** の ScopeWeaver の変更は、製品名、英語を既定・韓国語を選択可能とする画面とメッセージ、ドキュメントと同梱エージェントの指針、初期設定・ビルド・起動・更新・パスワードリセットのプロンプト、レポートとエージェントの言語処理、配布物の命名を対象にしています。実行ファイルは `scopeweaver`（Windows は `scopeweaver.exe`）、アーカイブ名は `scopeweaver-<version>-<os>-<arch>.zip` です。Docker Compose は、チェックアウトしたソースをローカルでビルドします。設定済みのリリースワークフローは、このリポジトリと GHCR を対象にします。

元の `LICENSE` は変更せず保持しています。元の作者、貢献者への謝辞、上流の変更履歴の帰属は ARTEX のままです。Go モジュール `github.com/Autumn-27/artex`、ソースのエントリーポイント `./cmd/artex`、`ARTEX_*` の設定契約、`artex` のデータベース既定値、`ARTEX` のログインユーザー名は、互換性のために保持します。

この変更日はリリースタグではなく、バイナリやコンテナーイメージの公開を主張するものではありません。`sidequestion/` の過去の検証資料は上流の実行を記述し、新しい ScopeWeaver の検証記録ではありません。過去の JSON の翻訳では、技術的識別子と測定値を保持し、説明文が翻訳であることを示します。

**2026-10-15** の変更では、任意のネイティブ Ollama プロファイル形式（`num_ctx`、`keep_alive`、`num_predict` を使う `/api/chat`）、新規フォーム用 Ollama テンプレート 3 種、キー不要のローカルプロファイル、プロファイル別の同時実行数、Ollama 対応のウォームアップ・圧縮・承認判定の既定値、任意の `local_llm_only` LLM ネットワーク方針を追加しました。`SCOPEWEAVER_LLM_*` と `SCOPEWEAVER_LOCAL_LLM_*` を、保持された `ARTEX_*` 契約より優先する別名として追加しました。既存の Anthropic、OpenAI、OpenAI Responses、カスタム URL、プロキシ、GLM テンプレートの動作は保持し、この方針は既定で無効です。

**2026-10-15** の続くネイティブ強化候補では、割り込みを行わず次の空き枠に緊急処理を受け入れる機能、実際のネイティブ起源の判定モデルの選択、スキーマで制約した出力、90 秒・ask の既定値、64K までのコンテキストに対する 72% での圧縮と 16/32 KiB のツール出力上限を追加しました。任意の厳密な接続先をループバックと明示した推論用 CIDR に絞り（LAN/Docker の移行を含む）、リダイレクト・プロキシを拒否し、ローカルの状態表示・ロールバックを維持しながら、すべてのエージェント検索と更新のネットワーク操作をブロックします。読み取り専用の GPU メモリー推定とモデル共有の警告、安全な判定設定の読み込み、英語・韓国語・簡体字中国語の画面テキストも含みます。これはアプリケーションの制御であり、ホスト全体のオフライン化やモデル品質の保証ではありません。依存関係、移行、モデルの自動取得、リリースは追加していません。[プロバイダーガイド](llm-providers.md)と[候補の検証](VERIFICATION.md#native-hardening-candidate--2026-10-15)を参照してください。

**2026-10-03** の追加変更では、サーバー翻訳の監査を完了し、GLM-5.3 の設定テンプレートと、必須の常時有効な推論への互換性を追加しました。テンプレートは既存のプロバイダーアダプターを使い、プロファイルを自動で作成・有効化しません。

その後、ARTEX のコミット `e2c8a23`、`86729b6`、`a951e4a` の上流修正をバックポートしました。本番 SSE の同一オリジン化、承認モデルのトークン集計の分離、初期パスワードのアトミックな作成と接続数を制限した DB プールを伴う、安全側に閉じる認証です。新しいメッセージとデプロイガイドを英語・韓国語で用意しました。バックポートのコミットで元の作者を明記し、他の ScopeWeaver の変更はそのまま保持しています。
