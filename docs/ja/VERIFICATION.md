<a id="running-database-backed-tests"></a>
## DB を使うテストの実行

`db`、`server`、`agent` は PostgreSQL を必要とします。接続先は環境変数 `ARTEX_TEST_DSN` **のみ**から解決し、アプリ自身の DSN（`ARTEX_PG_DSN` / `config.json`）には戻りません。実行中アプリの本番 DB を `go test` が変更しないための意図した設計です。

- **`ARTEX_TEST_DSN` が未設定** → DB を使うすべてのテストをスキップし、DB には
  触れません。
- **`ARTEX_TEST_DSN` に使い捨て DB を設定** → その DB に対して実行します。
- **`ARTEX_TEST_DSN` がアプリと同じ DB に解決**（同じホスト、
  ポート、DB 名）→ 接続前に `refusing to run tests against the live database; point ARTEX_TEST_DSN at a throwaway DB` で即座に失敗します。

最も簡単な実行方法:

```bash
make test-db
```

`make test-db`（`scripts/test-db.sh`）は、`sw_user_test` 所有の `scopeweaver_test_<pid>` を作成し、`ARTEX_TEST_DSN` を向け、`go test ./db/ ./server/ ./agent/ -count=1` を実行して、失敗時も終了時に削除します。ローカル PostgreSQL に合わせて `TEST_DB_ROLE`、`TEST_DB_HOST`、`TEST_DB_NAME` を上書きできます。DB 名は `scopeweaver_test_`（アダプター E2E は `scopeweaver_adapter_`）で始めてください。

自分で管理する DB で一部だけ実行する場合、`ARTEX_TEST_DSN` を設定し `go test` を直接呼びます:

```bash
export ARTEX_TEST_DSN='postgres://sw_user_test@/scopeweaver_test_1?host=/tmp&sslmode=disable'
go test ./server/ -run TestSomething -count=1
```
